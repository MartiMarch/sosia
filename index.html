Introduction

Sosia has been created to achieve a high-performance secrets orchestrator in a distributed scenario (within a cluster and across geographically distributed clusters). For now, it is a personal project, but the idea is use it in my own environments, focusing on the need to combine cloud and on-premise infrastructure.

So, if you decide to use it, please take in consideration that the entry project is under the MIT license, and there are no guarantees or any kind of technical support in case of failure (perhaps in the future, if objectives are met...).


Objectives

Provide a high-availability system resilient to failures in distributed environments based on containers, specifically kubernetes, while ensuring security principles such as confidentiality, integrity and authentication. Additionally, the system offers the capability to audit and track events, with the ability to integrate with external tools to define its behavior.

Roadmap

Features are linked with labels, as PR0, which means 'Principal Release 0'. It is used to create features list to divide the roadmap with the next development phases:

  • PR0: Single pod capable of interacting with the database. Includes 'basic' feature applications and manages basic secret orchestration.
  • PR1: Supports the creation of clusters within Kubernetes clusters, enabling parallel processing of requests and managing database data without creating conflicts.
  • PR2: Clusters can communicate with other clusters and create data replicas using custom rules.
  • PR3: Sosia can connect to external systems and interact change expected behaviour dynamically based on events.

Concepts

Secret

Confidential content that will be orchestrated by Sosia. It includes a unique ID (within namespace), a description, a list of labels, a reference to environment variables used to encrypt/decrypt and the name of the algorithm [AES256, AES-GCM, ChaCha20-Poly1305, RSA, Twofish].

{
  "id": "mysecretid",
  "content": "fakePassword1234",
  "description": "A secret description",
  "key": "MY_ENVIRONMENT_VARIABLE_POINTING_ENCRYPTION_KEY",
  "labels": ["custom label 1", "custom label 2"],
  "encrypt": "AES-256"
}

To use a custom encrypt/decrypt algorithm, parameter encrypt must be set to CUSTOM. The referenced environment variable (key) will then be used as the encryption key to process Kafka message. This means there could be a service monitoring the Sosia encryption topic.The secrets used during this process must be configured on both sides: Sosia and the external service. Additionally, topic configurations can be established. Please refer to the configuration section for more details. 


{
  "id": "mysecretid",
  "content": "fakePassword1234",
  "description": "A secret description",
  "key": "MY_ENVIRONMENT_VARIABLE_POINTING_ENCRYPTION_TOPIC_KEY",
  "labels": ["custom label 1", "custom label 2"],
  "encrypt": "CUSTOM"
}
